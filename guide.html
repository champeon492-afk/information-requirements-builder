Know the screen

The left side organizes files and specifications. The main area edits the currently selected file and specification.

1 Expand a colored file group and select an IFC specification.
2 Change the current file name or color; close it when finished.
3 Enter the delivery title, version, purpose, milestone, and author.
4 Review project and model setup checks.
5 Define which IFC objects the selected specification applies to.
6 Add and edit the information those objects must contain.

Work with multiple IDS files

Each file has its own color. Its IFC specifications are nested underneath, so the list stays compact. On a desktop screen, the file list stays visible while the main page scrolls.

  1. Open a file

    Choose Import IDS files and select one or several .ids files. The browser reads them into this workspace.

  2. Or create a new file

    Choose New IDS. Enter document details, then select Add specification.

  3. Switch, rename, and color

    Select a colored file heading on the left. Change its name in the Current IDS bar. Open Color to select a tile or choose a custom color.

Save before leaving: The open workspace lives in browser memory. Download changed files before refreshing or closing the page.

Project and model setup

Use Project and model setup in the left sidebar to jump to these checks. The labels describe what IDS can express; they are not test results from an IFC model.

YES

Direct requirement

For example, require IfcProject.Name or IfcBuilding.Name. Select Add check to insert it into the current IDS.

PARTLY

Relationship check

For example, specify that a building is part of a site. IDS checks the stated relationship; broader spatial structure still needs model review.

NO DIRECT IDS CHECK

Separate IFC validation

Coordinate reference system, map conversion, project units, and true north need an IFC model check. These rows cannot be added as IDS rules here.

When a setup row says Included in current IDS, that means the requirement was authored in the selected IDS file. It does not mean an IFC model passed the check.

Write a specification and its requirements

  1. Select an IFC specification

    Choose an entity row under the current file, or use Add specification.

  2. Define its scope

    Set the specification name, IFC version, applicable IFC entity, and minimum and maximum occurrences. Suggested IFC values appear as you type.

  3. Add a requirement

    In Requirements, select ＋ Add requirement. Pick a facet type and complete the fields in the dialog.

  4. Set value and cardinality

    Where available, choose an exact value, XML Schema pattern, or allowed-value list. Choose required, optional, or prohibited as appropriate.

  5. Review and edit

    Use the requirements table to search, edit, or delete rows. The table shows the facet, value rule, and cardinality.

Check and download

  1. Run checks

    Use Run checks at the bottom of the builder. Fix blocking issues, such as a missing title, missing IFC entity, or invalid occurrence range.

  2. Review XML if needed

    Select Preview XML to inspect the generated XML for the current IDS file.

  3. Download your result

    Use Download current IDS for one file or Download all ZIP for every open IDS file.

Preview XMLDownload all ZIPDownload current IDS

The builder can check its own document structure. For a deliverable, validate the downloaded IDS with an IDS validator and check the IFC model separately.

Advanced XML restrictions in an imported IDS are preserved on export, but some cannot be edited in the form.
